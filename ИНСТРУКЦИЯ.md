# AmazingBot — инструкция: установка и использование

Бот для **Amazing Online** (Windows-клиент): автоматически поливает, удобряет, лечит паразитов,
сажает, собирает/клонирует грядки, сам пополняет лейку и инвентарь из багажника машины,
занимает машину при её респавне. Управляется из оконного меню (либо из консоли).

> ⚠ Использование ботов может нарушать правила игры — аккаунт могут заблокировать.
> Бот для личной рутины на своём аккаунте; используете — на свой риск.

---

## 1. Что понадобится

| Что | Зачем |
|---|---|
| Windows 10 или 11 | бот работает через Win32 (BitBlt, SendInput) |
| [.NET 8 SDK](https://dotnet.microsoft.com/download) (не только runtime!) | сборка бота |
| Amazing Online в **оконном** или безрамочном режиме | полноэкранный эксклюзивный режим не захватывается |
| Масштаб Windows 100% (или бот и игра запущены с одинаковыми правами) | чтобы клики попадали точно |
| 15–30 минут на первую настройку | шаблоны и маршруты вырезаются один раз |

Проверить, что SDK установлен:

```powershell
dotnet --version
```

(должно печатать 8.x.x)

## 2. Установка

### Шаг 1. Скачайте код

```powershell
git clone https://github.com/FsbAidol/fyiuj-.git
cd fyiuj-
```

(или просто положите папку проекта к себе любым способом)

### Шаг 2. Соберите

```powershell
dotnet build -c Release
```

### Шаг 3. Сделайте рабочую папку

Создайте папку, например `C:\AmazingBot\`, и положите туда рядом:

```
C:\AmazingBot\
  ├── AmazingBot.exe        ← оконное меню (или AmazingBot.App.exe после publish, см. ниже)
  ├── config.json           ← копия configs\config.example.json, подправленная под вас
  ├── templates\            ← сюда BMP-шаблоны
  ├── routes\               ← сюда маршруты (создастся само)
  └── logs\                 ← сюда логи (создастся само)
```

Проще всего просто работать из корня репозитория — все пути в `config.json`
относительные (`templates`, `routes`, `logs`).

### Шаг 4 (необязательный, «как у взрослых»). Один exe без консоли

```powershell
dotnet publish src\AmazingBot.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Готовый файл в `src\AmazingBot.App\bin\Release\net8.0-windows\win-x64\publish\AmazingBot.App.exe`.
Его можно перенести на машину с Windows без .NET — всё внутри.

### Шаг 5. Первоначальный конфиг

```powershell
copy configs\config.example.json config.json
```

Откройте `config.json` в блокноте и поправьте под себя (см. раздел 6 «Разбор настроек»).
Минимум, что нужно поменять сразу: `windowTitleContains`, горячие клавиши хотбара,
 `litersPerBed` / `canCapacityLiters`, стартовый инвентарь.

## 3. Запуск

### Оконное меню (рекомендуется)

```powershell
dotnet run --project src\AmazingBot.App -c Release
```

### Консольное меню (те же функции текстом)

```powershell
dotnet run --project src\AmazingBot -c Release
```

### Без меню (для скриптов/проверок)

```powershell
AmazingBot.exe --once              # один проход по грядкам и выход
AmazingBot.exe --screenshot        # сохранить screenshot.bmp окна игры
AmazingBot.exe --check-templates   # что распознаётся на экране прямо сейчас
AmazingBot.exe --record-route X    # записать маршрут X (F10 — конец)
AmazingBot.exe --calibrate-beds    # визуальная разметка грядок на кадре
AmazingBot.exe --config PATH       # использовать другой config.json
```

## 4. Первый запуск — по шагам

1. **Запустите Amazing Online в оконном режиме** и зайдите на участок с грядками.
2. **Запустите оконное меню** (раздел 3).
3. Вкладка **«Настройки»**: впишите кусок заголовка окна в «Заголовок окна игры содержит»
   (например `Amazing Online`) → «Сохранить все настройки».
4. Вкладка **«Простая настройка»**: откройте панель грядки в игре, выберите тип образца и нажмите «Снять образец с экрана…». Обведите маленький уникальный индикатор в окне выбора и сохраните. Снимите образцы для «Растение есть», «Пустая грядка», «Урожай готов», «Нужно удобрение», «Мало воды», «Воды достаточно» и нужной кнопки сбора/клонирования.
5. Для вредителей добавьте строку в таблицу на той же вкладке: имя, ключ образца (например `bug_spider`), название химиката/ключ и слот хотбара, количество химиката. Выделите строку → «Снять образец выбранного жука…» → обведите иконку в игре. Сохраните таблицу.
6. Вкладка **«Грядки»** → «Отметить грядки на превью…». Существующие метки остаются на кадре. Щёлкайте по центру новых грядок; правый клик удаляет отдельную метку, «Очистить» сбрасывает весь список. Нажмите «Сохранить точки». Бот сделает кадр игры без своего окна; вводить координаты и нажимать F8/Insert не нужно. После разметки не меняйте камеру/масштаб.
7. На вкладке **«Простая настройка»** нажмите «Проверить образцы». Для предметов багажника и редких уведомлений при необходимости используйте вкладку «Шаблоны» и руководство `templates/README.md`.
8. Вкладка **«Маршруты»**:
   - выберите имя (`barrel_main`) → «● Начать запись» → откройте игру в нужное место →
     **дойдите до бочки, наберите воду и ВЕРНИТЕСЬ к грядкам** → нажмите **F10**;
   - если есть резервная бочка — то же самое с именем `barrel_backup`;
   - то же для машины: имя `to_car`, от грядок к багажнику и обратно.

   Маршрут пишется один раз и играется ботом как есть, включая возврат.
9. Конфиг: пропишите в `config.json`, где что лежит (`watering.mainBarrelRoute` и т.д. —
   по умолчанию уже `barrel_main`, `barrel_backup`, `to_car`) и сколько у вас стартовых предметов
   (`inventory`).
10. Вкладка **«Главная»** → «▶ ЗАПУСТИТЬ БОТА». Смотрите журнал. Если что-то не так —
    **F12** или кнопка «■ СТОП».

## 5. Что есть в меню

### Оконное меню (AmazingBot.App)

| Вкладка | Что умеет |
|---|---|
| **Простая настройка** | Обучение образцам по снимку экрана; таблица вредитель → химикат/слот/количество; проверка образцов |
| **Главная** | Запуск/стоп бота; режим (сбор/клонирование); интервал проверки; анти-афк; авто-отключение; журнал с цветами и кнопкой «Очистить» |
| **Грядки** | Разметка грядок кликами на превью с нумерацией и удалением меток; сохранение координат; переименование и удаление |
| **Маршруты** | Запись маршрута с именем (`barrel_main`, `barrel_backup`, `to_car` или своё), список сохранённых маршрутов |
| **Шаблоны** | Сохранение скриншота окна; проверка, какие шаблоны видны на экране и каких не хватает |
| **Настройки** | Заголовок окна, точность (matchThreshold), литры лейки/за клик/на грядку/во фляге, клавиши хотбара, анти-афк, уровень лога |
| Строка состояния | Статус бота + напоминание про F12 |

### Консольное меню (AmazingBot)

Те же функции нумерованным списком: 1 — запуск, 2 — один проход, 3 — записать маршрут,
4 — калибровка грядок, 5 — скриншот, 6 — проверка шаблонов, 7 — настройки, 8 — сводка, 9 — перечитать конфиг, 0 — выход.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| **F8** | Не нужен для разметки грядок — в Amazing делает скриншот |
| **F10** | (в записи маршрута) закончить запись |
| **F12** | **экстренная остановка бота в любой момент** |

## 6. Разбор настроек config.json

Комментарии `//` в JSON разрешены — конфиг можно подписывать.

```jsonc
{
  "windowTitleContains": "Amazing Online",   // кусок заголовка окна игры
  "checkIntervalSeconds": 20,                // как часто проверять грядки
  "autoDisableOnAllBedsDone": true,          // самоотключение после сбора ВСЕХ
  "harvestMode": "harvest",                  // "harvest" (собрать) или "clone" (клонировать)
  "matchThreshold": 0.82,                    // строгость распознавания (больше — строже)

  "watering": {
    "canCapacityLiters": 10,                 // вместимость лейки
    "litersPerClick": 1,                     // сколько воды льёт одно нажатие
    "litersPerBed": 3,                       // норма полива на грядку
    "flaskLiters": 5,                        // воды из одной фляги
    "useFlaskFromInventory": true,            // сначала тратить фляги, потом бочки
    "canHotbarKey": "3", "flaskHotbarKey": "2",  // слоты хотбара
    "mainBarrelRoute": "barrel_main",        // маршрут к основной бочке
    "backupBarrelRoute": "barrel_backup",    // маршрут к резервной ("" — нет резерва)
    "barrelRefillKey": "E",                  // набрать воду у бочки
    "mainBarrelEmptyTemplate": "",            // шаблон «бочка пуста» (необязательно)
    "canTemplate": "can",                    // целая лейка
    "brokenCanTemplate": "can_broken"         // сломанная лейка
  },

  "parasites": [ {                              // паразит → химикат
    "name": "блоха", "parasite": "parasite_flea",
    "chemical": "chem_flea", "hotbarKey": "4"
  } ],

  "trunk": {                                    // багажник машины
    "route": "to_car", "openKey": "T", "closeKey": "Escape",
    "items": [
      { "template": "flask",       "name": "flask",       "takeCount": 3 },
      { "template": "fertilizer",  "name": "fertilizer",  "takeCount": 2 },
      { "template": "seed_example","name": "seed",        "takeCount": 10 },
      { "template": "chem_flea",   "name": "chem_flea",   "takeCount": 2 }
    ]
  },

  "car": {                                      // респавн транспорта
    "respawnNoticeTemplate": "transport_respawn",
    "claimRoute": "to_car", "claimKey": "F",
    "checkIntervalSeconds": 10
  },

  "inventory": {                                 // сколько чего есть на старте
    "flasks": 3, "fertilizer": 5, "seeds": 10,
    "chemicals": { "chem_flea": 2 }
  },

  "antiAfk": { "enabled": true, "intervalSeconds": 60, "keys": [ "Space" ], "mouseWiggle": true }
}
```

Важно: `trunk.items[].name` для химикатов = ключ в `inventory.chemicals` = `parasites[].chemical`.
Для обычных предметов: `flask`, `fertilizer`, `seed`.

## 7. Как бот себя ведёт

Цикл повторяется каждые `checkIntervalSeconds`:

1. Респавн транспорта? → едет и занимает машину.
2. Чего-то закончилось / лейка сломалась? → едет к машине, пополняет из багажника.
3. Идёт по грядкам по очереди:
   - грядка готова → Собрать/Клонировать (по `harvestMode`), грядка считается «закрытой»;
   - паразит → применяет нужный химикат;
   - просит удобрение → удобряет;
   - низкая влажность → поливает **ровно до нормы** (считает литры и нажатия сам);
   - пусто → сажает семя.
4. **Все грядки собраны/клонированы** и включено `autoDisableOnAllBedsDone` — бот сам выключается
   (два звуковых сигнала и запись в журнале).
5. Если лейка пуста — сначала фляги из инвентаря; потом бочка по маршруту; если основная
   пуста — резервная; если обе пусты — полив останавливается, в журнале будет сообщение.

## 8. Частые проблемы и решения

| Симптом | Что делать |
|---|---|
| «Окно игры не найдено» | Проверьте `windowTitleContains` (впишете кусок реального заголовка), игра в окне/безрамочном режиме |
| Клики мимо / не работают клавиши | Запускайте бота с теми же правами, что и игра (оба не от админа или оба от админа). Масштаб Windows 100% |
| Шаблон «не виден» | Переснимите: возьмите контрастнее/уникальнее фрагмент; уменьшите `matchThreshold` до 0.72–0.78 |
| Бот поливает не до нормы | Проверьте `litersPerBed`, `litersPerClick`, `canCapacityLiters`; следите за `moisture_low`/`moisture_full` шаблонами |
| Фляги/химикаты кончились, а бот «не замечает» | Пополните `inventory` в конфиге вручную — бот верит этому числу, а не экрану |
| Бочка пуста, но бот не идёт к резервной | Задайте `backupBarrelRoute` и (рекомендуется) `mainBarrelEmptyTemplate` — шаблон «пусто» |
| Лейка не выбирается в хотбаре | Поправьте `canHotbarKey` / `flaskHotbarKey` под свою раскладку |
| F12 не останавливает | Игра перехватывает F12? Запустите игру и бота от одного уровня прав; либо попросите добавить другую паник-клавишу |
| Игра обновилась, всё «сломалось» | Переснимите шаблоны (кнопки/иконки могли измениться) |
| `logs/` пустой | Проверьте `logsDir` в конфиге и права на запись в папку |

Логи лежат в `logs\amazingbot-YYYYMMDD.log` и дублируются в журнал на вкладке «Главная».

## 9. Обновление и удаление

**Обновить:** `git pull` → `dotnet build -c Release`. Ваш `config.json`, `templates/`, `routes/`
не трогаются (они в `.gitignore` / рядом, а не в коде).

**Удалить:** закройте бота, удалите папку проекта или просто `AmazingBot.exe` и `config.json`.
Никаких следов в системе не остаётся (кроме папки `logs/`).

---

## 10. Если ничего не помогает

1. `AmazingBot.exe --once` — один проход с подробным журналом;
2. `logLevel: "Debug"` в конфиге — максимум деталей;
3. пришлите последний файл из `logs/` — по нему видно, на каком именно шаге бот застрял.
